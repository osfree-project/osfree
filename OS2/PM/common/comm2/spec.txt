# ТЗ: FreePM транспортный слой (`F_Link`, 3 backend) + PMCLIENT per-thread

Версия: актуальна на текущее состояние кода. Транспортный слой собран (pmtcp, pmpipe, pmshm) на OS/2 и Win32. PMCLIENT — следующий этап.

---

## Часть I. Архитектурные принципы

### I.1. Слои и граница клиент/сервер

```
Application (клиент)               Application (сервер: реализация PM)
   │                                   │
   ▼                                   ▼
── L6 Wire ─────────────────────────────────────────────
PMGPI/PMMERGE (marshaling)      Fs_Server::HandleGpiCall/WinCall
   │                            + SendHeader (decode/encode)
   ▼                               ▲
── L5 Session ───────────────────────────────────────────
PMCLIENT                         Fs_Server (routing)
  aConns[tid], keepalive,          Fs_Process / Fs_Thread / Fs_Hab
  reconnect                        MonitorLoop (grace expiry)
   │                               ▲
   ▼                               │
── L4 Transport ─────────────────────────────────────────
Fc_Trn* (shared + backend)      Fs_Trn* (shared + backend)
   │                               ▲
   └──── F_Link ─┬─ TcpLink         │
                 ├─ PipeLink        │
                 └─ ShmLink ────────┘
                 (one backend per DLL)
```

**Граница клиент/сервер** проходит по L4/L3 (транспорт). L4–L6 симметричны. L7 асимметричен: клиент — внешнее приложение, сервер — реализация PM.

**L4** — абстрактный транспорт. Публичный API (`Fc_Trn*`/`Fs_Trn*`, 11 функций) одинаков для всех транспортов. Конкретный транспорт (`TcpLink`, `PipeLink`, `ShmLink`) спрятан за `F_Link`, выбирается загрузкой соответствующего backend-DLL.

**GOCA** — L7-внутренний формат сервера, не сетевой слой. На wire не уходит (в текущей модели NGpi). OSI-терминология в рабочих документах не используется.

### I.2. Per-thread модель

| Сущность | Где | Ключ | Владелец |
|---|---|---|---|
| **Транспортное соединение** | обе стороны | `obj` (opaque) | backend DLL (`F_Link` instance) |
| **Клиентский поток** | клиент | `tid` (thread id) | PMCLIENT (`aConns[tid]`) |
| **Серверный поток** | сервер | `pClient` (opaque, = `obj`) | backend `Fs_ClientThreadProc` |
| **Сессия сервера** | сервер | `idClient` (монотонный) | `Fs_Process` |
| **HAB** | сервер | `iHab` (монотонный) | `Fs_Hab` |
| **Клиентский TID в сессии** | сервер | `(idClient, tid)` | `Fs_Thread` |

**Один клиентский поток ↔ одно транспортное соединение ↔ один серверный `Fs_ClientThreadProc` ↔ один `Fs_Thread`.**

`idClient` — process-wide. `(idClient, tid)` — ключ HAB. `iHab` — монотонный, уникальный на сервере.

### I.3. Что убрано

| Убрано | Почему |
|---|---|
| `F_CMD_CLIENT_CONNECT` / `F_CMD_CLIENT_EXIT` | Первое, что делает поток — `WinInitialize`; сессия умирает с последним HAB |
| `CONNECT` handshake в PMCLIENT | Заменён на первый `NWinInitialize` (bootstrap) |
| `EXIT` в DETACH | PMCLIENT закрывает транспорт через `Fc_TrnDisconnect` |
| `DllMain` / `_DLL_InitTerm` в backend | WSA в DETACH уже может быть выгружен; клиент делает явный disconnect |
| `pF_pipe` / `g_shutdownCb` в backend | PMCLIENT — единственный держатель `obj` |
| `Fs_Session` / `Fs_SessionList` | Сессия — агрегат (`idClient`), а не сущность |
| `pmque` / `QueueLink` | Заменён на `pmshm`/`ShmLink` — OS/2-идиома queue + shared memory |

## Часть II. Соглашение об именах

### II.1. Схема префиксов

| Префикс | Значение |
|---|---|
| **`Fc_`** | Клиент (client) — код, исполняемый в клиентском процессе |
| **`Fs_`** | Сервер (server) — код, исполняемый в серверном процессе |
| **`F_`** | Общий (common) — код на обеих сторонах (debug, config, wire headers) |

### II.2. Квалификатор слоя

| Квалификатор | Слой | Пример |
|---|---|---|
| **`Trn`** | Transport (L4) | `Fc_TrnConnect`, `Fs_TrnRunListener` |
| **`Ses`** | Session (L5) | `Fc_SesBeginThread`, `Fc_SesPostCommand` |
| (нет) | Common / cross-cutting | `F_DbgPrint`, `F_DbgCtxEnterf` |

Серверная сессия (`Fs_Process`, `Fs_Thread`, `Fs_Hab`, `Fs_Server`) — C++ классы, не функции. Клиентская сессия — DLL-экспорты (`Fc_Ses*`).

### II.3. Глаголы (PM queue convention)

| Глагол | Семантика |
|---|---|
| **`Post`** | Асинхронная запись, без ожидания ответа |
| **`Send`** | Запись + ожидание ответа (sync) |
| **`Get`** | Блокирующее чтение |
| **`Connect` / `Disconnect`** | Управление соединением |
| **`Run`** | Запуск цикла (accept-loop, не возвращает) |

Консистентность обязательна на обоих слоях (Trn и Ses).

## Часть III. L4 Transport — `F_Link` + 3 backend

### III.1. Схема реализации

```
┌────────────────────────────────────────────────────────────┐
│                  Публичный API (11 exports)                │
│   shared/Fc_trn.cpp (7)        shared/Fs_trn.cpp (2)       │
│   backend (Fc_TrnConnect, Fs_TrnRunListener)               │
└─────────────────────────┬──────────────────────────────────┘
                          │ ((F_Link *)obj)->Send/Recv/...
                          ▼
┌────────────────────────────────────────────────────────────┐
│                F_Link abstract interface                   │
│  Open / Accept / Handshake / Send / Recv / Close           │
└─────────────────────────┬──────────────────────────────────┘
                          │
        ┌─────────┬───────┴───────┐
        ▼         ▼               ▼
    TcpLink   PipeLink        ShmLink
    (pmtcp)   (pmpipe)        (pmshm)
```

### III.2. Публичный API

#### Клиентский (`Fc_Trn*`)

| Функция | Где | Семантика |
|---|---|---|
| `Fc_TrnConnect(char *host, ULONG *obj)` | backend | Создать соединение + handshake. `*obj = 0` при ошибке. |
| `Fc_TrnDisconnect(void *obj)` | shared | Закрыть. `NULL` → no-op. |
| `Fc_TrnPostCommand(void *obj, int cmd, int par)` | shared | Async write 8B. |
| `Fc_TrnPostData(void *obj, void *buf, int len)` | shared | Async write N байт. |
| `Fc_TrnGetData(void *obj, void *buf, int *len, int size)` | shared | Blocking read ровно `size` байт. |
| `Fc_TrnSendCommand(void *obj, int cmd, int par)` | shared | `PostCommand` + `GetData(4)`. Возврат — `retcode` или `-1`. |
| `Fc_TrnSendCommandData(void *obj, int cmd, int par, void *buf, int len)` | shared | `PostCommand` + `PostData` + `GetData(4)`. |

#### Серверный (`Fs_Trn*`)

| Функция | Где | Семантика |
|---|---|---|
| `Fs_TrnRunListener(void *handler, void *disc_cb)` | backend | Listener, accept-loop, per-conn thread. Не возвращает (кроме setup-ошибки). |
| `Fs_TrnGetCommand(void *obj, int *cmd, int *par)` | shared | Blocking read 8B. |
| `Fs_TrnGetData(void *obj, void *buf, int *len, int size)` | shared | Blocking read ровно `size` байт. |
| `Fs_TrnPostData(void *obj, void *buf, int len)` | shared | Async write N байт. |

### III.3. Контракты

**`obj`** — opaque handle. Один `obj` = одно соединение.

**`NULL obj`** — все функции возвращают ошибку, кроме `Fc_TrnDisconnect(NULL)` → `0`.

**`NULL buf` при `len > 0`** — `PostData` / `GetData` / `SendCommandData` возвращают ошибку, не вызывая транспорт.

**`*obj` при ошибке `Fc_TrnConnect`** — всегда `0`.

**`datalen` / `len`** — в байтах, везде.

**Return-value convention:** `-1` (0xFFFFFFFF) зарезервирован под transport errors в `Fc_TrnSendCommand`/`Fc_TrnSendCommandData`. Серверные handlers **не должны** возвращать `-1` как business reply.

**WSA refcount (только `TcpLink`):** `TcpLink` ctor/dtor, `WSAStartup`/`WSACleanup` под mutex, созданным один раз под `InterlockedCompareExchange` guard.

**Адрес (`Fc_TrnConnect`) — backend-specific:**
- `TcpLink`: `"host"` или `"host:port"`
- `PipeLink`: `NULL` → `\PIPE\FREEPM` (OS/2) / `\\.\pipe\FREEPM` (Win32)
- `ShmLink`: `NULL` → `\QUEUES\FREEPM`

### III.4. `F_Link` abstract interface

| Метод | Семантика |
|---|---|
| `Open()` | client: connect; server: create listener. Возврат 0 / -1. |
| `Accept(F_Link**)` | server: accept, allocate new `F_Link`, вернуть через `*ppNew`. |
| `Handshake()` | FreePM handshake. Таймаут — per-backend. Возврат 0 / `HAND_SHAKE_ERROR`. |
| `Send(const void*, int)` | Ровно `cbData` байт. Цикл на partial, EINTR-retry (где применимо). |
| `Recv(void*, int*, int)` | Ровно `cbBuffer` байт. Peer-close → `*pcb` = прочитано, -1. |
| `Close()` | idempotent. |

**Handshake исполняется в `Fs_ClientThreadProc`**, не в accept-loop. Медленный клиент не блокирует приём остальных.

### III.5. Backend реализации

| Backend | Класс | Особенности |
|---|---|---|
| `pmtcp` | `TcpLink` | BSD sockets. Non-blocking connect + select с таймаутом. Handshake per-chunk timeout (`PMC_HANDSHAKE_TIMEOUT_MS = 3000`). WSA refcount в ctor/dtor. `SO_KEEPALIVE` включён, но без настройки (OS default ~2h); PMCLIENT PING — основной механизм liveness. `SD_SEND` определён как 1 для OS/2. |
| `pmpipe` | `PipeLink` | OS/2 named pipes + Win32 эмуляция через `CreateNamedPipeA`. Byte mode. Client retries `DosOpen` on `ERROR_PIPE_BUSY` via `DosWaitNPipe`, ограничено `FREEPM_PIPE_TIMEOUT`. Listener recovery: новый instance создаётся **до** hand-off, при permanent fail — disconnect клиента, listener сохранён. Cap: `FREEPM_PIPE_MAX_INST - 1` одновременных клиентов. |
| `pmshm` | `ShmLink` | OS/2 queues (уведомления) + shared memory (данные). Canonical OS/2-идиома: queue element = `{slot, length}` (8 байт), данные — в shared memory. Handshake — `QmsHello {u8 version; u32 pid; u32 tid}` (9 байт) через `\QUEUES\FREEPM`, эхо через C_. Имена вычисляются из `(pid, tid)`. Data region: `QMS_SLOT_SIZE = 1 MB` на сообщение, `QMS_SLOTS = 1`. `PAG_READ \| PAG_WRITE` без `PAG_COMMIT`. Recv peer-death — idle timeout 60s; Accept handshake — 30s. |

**Платформенные различия** полностью поглощены `F_platform.h`. Backend-код использует только OS/2 API. Namespace-имена (`\PIPE\`, `\QUEUES\`, `\SHAREMEM\`) строятся в backend с учётом платформы.

### III.6. Queue emulation (Win32)

`F_platform.h` эмулирует `Dos*Queue` через shared memory + named objects (Win32). **Слот очереди = 16 байт** (`WQ_MAX_ELEMENT`), `WQ_MAX_ELEMENTS = 8`. Этого достаточно для control-сообщений:
- `QmsElem` (slot, length) — 8 байт
- `QmsHello` (version, pid, tid) — 9 байт

Данные **не проходят через очередь** в pmshm — они идут через shared memory. Поэтому 16-байтный лимит — не ограничение на user payload.

**Через очередь проходят только control-сообщения.** Для произвольных данных — shared memory (pmshm) или pipe/TCP (pmpipe/pmtcp).

### III.7. Сборка

Одна DLL на backend: `pmtcp.dll`, `pmpipe.dll`, `pmshm.dll`.

```
shared/F_wire.cpp
shared/Fc_trn.cpp
shared/Fs_trn.cpp
<backend>/F_<name>.cpp
```

11 exports, identical ordinals (1–11):

```
Fc_TrnConnect.1, Fc_TrnDisconnect.2, Fc_TrnPostCommand.3,
Fc_TrnPostData.4, Fc_TrnSendCommand.5, Fc_TrnSendCommandData.6,
Fc_TrnGetData.7, Fs_TrnRunListener.8, Fs_TrnPostData.9,
Fs_TrnGetCommand.10, Fs_TrnGetData.11
```

Клиент выбирает backend через `Fc_SesInit` (config `fpm.ini`). Сервер — статически в `Fs_TrnRunListener`.

## Часть VI. Wire protocol

### VI.1. Framing

```
PmcPostCommand(cmd, par):   cmd (4B) + par (4B)         = 8B header
PmcSendData(buf, len):      buf (len B)                  = N data
Reply (header + payload):   FPM_RESP_HEADER (16B) + payload
```

Header всегда 8 байт: `cmd` (ULONG) + `par` (ULONG). `cmd` = `F_CMD_MAKE(class, opcode)`.

### VI.2. Handshake

Базовый F_Link handshake — 9 байт в обе стороны:
- Client → Server: `"pIpEtEsT\0"`
- Server → Client: `"PiPeTeSt\0"`

`pmshm` использует расширенный handshake: `QmsHello {u8 version; u32 pid; u32 tid}` (9 байт) через `\QUEUES\FREEPM`, эхо — те же 9 байт через C_. `Handshake()` после этого no-op.

**Чтение — ровно 9 байт.** Over-read — баг.

### VI.3. Команды

| Class | Opcode | Семантика | Bootstrap? |
|---|---|---|---|
| CORE | `F_CMD_CLIENT_RECONNECT` | Резюм сессии | да |
| CORE | `F_CMD_CLIENT_PING` | Touch | нет |
| CORE | `F_CMD_DB_PRINT` / `F_CMD_FATAL_COMMON` | Debug | нет |
| WIN | `NWinInitialize` | Bootstrap Process+Thread+Hab | **да** |
| WIN | `NWinTerminate` | Destroy Thread+Hab | нет |
| WIN | `NWinGetLastError` | Query lastError | нет |
| GPI | `NGpi*` | GPI dispatch | нет |
| GORDER | `OCODE_*` | GOCA passthrough (отложено) | нет |

**`cmd == 0` = close.** `Fs_ClientThreadProc` при `cmd == 0` завершает recv-loop, вызывает `disc`, закрывает. Клиенты **не должны** использовать `cmd == 0` как бизнес-команду. Legacy поведение Gen 1, сохранено для совместимости.

### VI.4. `NWinInitialize` payload

```
data    = tid
payload = { ULONG clientid }   ; 0 для первого потока процесса
reply   = iHab (ulResult)
        + F_CLIENTCONFIG (только если clientid == 0)
```

### VI.5. `NWinTerminate` payload

```
data    = iHab
payload = { ULONG tid }
reply   = ulResult = 1/0
```

### VI.6. `RECONNECT` payload

```
data    = idClient
payload = { ULONG tid }
reply   = F_CLIENTCONFIG (или error)
```

### VI.7. `datalen` / `len`

Байты, везде.

## Часть VII. Стратегия тестирования

### VII.1. Принцип

**Транспортные тесты** (`test_<backend>.exe`):
- Собираются с конкретным backend `.cpp` + `shared/*.cpp` + headers.
- Не линкуются с `init.cpp` (PMCLIENT), `pmserver.cpp`/`dispatch.cpp`/`Fs_server.cpp`.
- Тестируют `Fc_Trn*`, `Fs_Trn*` изолированно.
- `F_Link`-классы (TcpLink, PipeLink, ShmLink) — internal, не экспортируются. Тесты используют только публичный API + raw sockets для edge cases.

### VII.2. Покрытие

| Группа | pmtcp | pmpipe | pmshm |
|---|---|---|---|
| A. Fc_TrnConnect (NULL obj, bad address, refused) | ✅ | ✅ | ✅ |
| B. Lifecycle (connect/disconnect) | ✅ | ✅ | ✅ |
| C. NULL obj / NULL buf | ✅ | ✅ | ✅ |
| D. Round-trip (PostCommand, PostData, SendCommand, SendCommandData, GetData) | ✅ | ✅ | ✅ |
| E. Partial frames / peer-close | ✅ (raw socket, cmd=0) | ✅ | ✅ (idle timeout) |
| F. Multi-conn (5 sequential) | ✅ | ✅ | ✅ |
| G. Oversize payload | — | — | ✅ (>1 MB) |

### VII.3. Ограничения тестов

`Fc_TrnConnect` хардкодит backend-адрес. `Fs_TrnRunListener` блокирует навсегда. Тесты запускаются в изоляции (PMSERVER не должен работать). Тест и listener в одном процессе.

| 1 | `Fc_TrnConnect`: NULL `obj` crash | `if (!obj) return PMC_ERR_OPEN;` — все backends |
| 2 | `static char PipeHost[256]` — race | Убран |
| 3 | `Recv(NULL, size>0)` — memcpy NULL | `if (!buf && size > 0) return -1;` в `Fc_TrnGetData`, `Fs_TrnGetData`, `PostData` |
| 4 | WSA mutex race в `TcpWsaRef` | `InterlockedCompareExchange` guard |
| 5 | `pmshm`: Recv висит на мёртвом peer | idle timeout 60s |
| 6 | `pmshm`: Accept висит на handshake | 30s timeout |
| 7 | `pmpipe`: listener death на transient fail | retry + disconnect-on-fail |
| 8 | `pmpipe`: client без retry на `ERROR_PIPE_BUSY` | `DosWaitNPipe` loop |
| 9 | handshake в accept-loop (slowloris) | перенос в `Fs_ClientThreadProc` |

### VIII.2. Известные ограничения (документированы)

| # | Ограничение | Где | Обход |

## Часть X. Резюме

**Архитектура:** client-server. L4–L6 симметричны. L7 асимметричен (клиент — external, сервер — PM-реализация). GOCA — L7-внутренний формат сервера.

**Именование:** `Fc_`/`Fs_`/`F_` + `Trn`/`Ses` + `Post`/`Send`/`Get`. Обязательное переименование `PmcSendData → Fc_SesPostData`.

**L4 Transport:** `F_Link` abstract + 3 backend (`TcpLink`, `PipeLink`, `ShmLink`). Одна DLL на backend, 11 exports identical (ordinals 1–11). 9 из 11 — `shared/`, 2 — backend-специфичны. `datalen` — байты.

**`pmshm`:** OS/2-идиома queue + shared memory. Queue несёт только 8-байтные уведомления `{slot, length}`, данные — в shared memory. Handshake — 9-байтный `{version, pid, tid}` через `\QUEUES\FREEPM`. Имена (C_, S_, C2S, S2C) вычисляются из `(pid, tid)` — на wire не передаются.

**`pmpipe`:** byte-mode pipe, retry на `ERROR_PIPE_BUSY`, listener recovery.

**`pmtcp`:** BSD sockets, non-blocking connect + select, handshake с per-chunk timeout, WSA refcount в ctor/dtor.

**Ограничение:** `pmshm` QMS_SLOT_SIZE = 1 MB на сообщение. Для больших GPI-bitmap — pipe/TCP. `F_platform.h` queue emulation — 16-байтный слот, только для control.

**PMCLIENT:** следующий этап. `Pmc* → Fc_Ses*`, `Fc_SesBeginThread`/`EndThread`, backend load по конфигу.

**Тесты:** транспортные (`test_pmtcp.exe`, `test_pmpipe.exe`, `test_pmshm.exe`) — отдельно от интеграционных (`pmtest.exe`).
